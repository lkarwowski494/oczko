## A1. Identyfikator App Group
**Po co:** aplikacja i rozszerzenie „Udostępnij do Oczka” wymieniają pliki przez wspólną grupę (`app.json` → `entitlements`, `targets/share/expo-target.config.js`; ADR-0011). Bez zarejestrowanej grupy podpis nie przejdzie.
**Gdzie:** https://developer.apple.com/account/resources/identifiers/list (Certificates, Identifiers & Profiles).
**Kroki** (Apple, „Register an app group”): 1) w pasku bocznym **Identifiers**, przycisk **+** u góry po lewej; 2) wybierz **App Groups**, **Continue**; 3) Description: `Oczko`, Identifier: `group.com.apps4brew.knitting` (dokładnie, małymi literami), **Continue**, **Register**.
**Źródło:** https://developer.apple.com/help/account/identifiers/register-an-app-group (odczyt 2026-11-01): „You’ll need to register one or more groups to enable app groups. Required role: Account Holder or Admin.” / „Select App Groups, then click continue. Enter a description and identifier, click Continue, then click Register.”
**Sprawdzenie:** zrzut listy Identifiers z filtrem „App Groups” pokazujący `group.com.apps4brew.knitting`.

## A2. Kontener iCloud
**Po co:** opcjonalna synchronizacja iCloud (CloudKit, ADR-0005) — `app.json` ma `icloud-container-identifiers`. Bez kontenera build z CloudKit się nie podpisze.
**Gdzie:** ta sama strona.
**Kroki** (Apple, „Create an iCloud container”): **+** → **iCloud Containers** → **Continue** → Description: `Oczko`, Identifier: `iCloud.com.apps4brew.knitting` → **Continue** → **Register**.
**Źródło:** https://developer.apple.com/help/account/identifiers/create-an-icloud-container (odczyt 2026-11-01): „You must have one or more iCloud containers to enable iCloud. Required role: Account Holder or Admin.”
**Sprawdzenie:** zrzut listy z filtrem „iCloud Containers”.

## A3. App ID aplikacji (`com.apps4brew.knitting`) — możliwości
**Po co:** App ID jest „listą dozwolonych” możliwości; aplikacja używa App Groups, iCloud (CloudKit) i powiadomień (`aps-environment` w `app.json`: CKSyncEngine potrzebuje powiadomień o zmianach).
**Kroki** (Apple, „Enable app capabilities”): 1) **Identifiers** → wybierz istniejący App ID `com.apps4brew.knitting` (jest z 0.1.0; jeśli go nie ma: „Register an App ID” — **App IDs** → **App** → Explicit, Bundle ID `com.apps4brew.knitting`) → **Edit**; 2) zaznacz **App Groups** → **Configure** → zaznacz `group.com.apps4brew.knitting` → **Continue** → **Assign** → **Done**; 3) zaznacz **iCloud** → w „Compatibility” wybierz **Include CloudKit support** → **Edit** → zaznacz `iCloud.com.apps4brew.knitting` → **Continue** → **Save**; 4) zaznacz **Push Notifications** (bez tworzenia certyfikatu — to potrzebne tylko przy komunikacji z APNs własnym certyfikatem); 5) **Save**; jeśli pojawi się ostrzeżenie, **Confirm**.
**Źródło:** https://developer.apple.com/help/account/identifiers/enable-app-capabilities (odczyt 2026-11-01): „Provisioning profiles that contain a modified App ID become invalid. You’ll need to regenerate the provisioning profiles that use that App ID.” (podpis automatyczny w `testflight.yml` tworzy je sam); „If you’re not using CloudKit, you may choose “Compatible with Xcode 5”; otherwise, choose “Include CloudKit support.”” Rejestracja: https://developer.apple.com/help/account/identifiers/register-an-app-id (odczyt 2026-11-01): „In-App Purchase is enabled by default for an explicit App ID.”
**Otwarte [DO USTALENIA]:** czy sam znacznik **Push Notifications** wystarczy dla CloudKit bez certyfikatu — Apple na tej stronie opisuje certyfikat jako wymagany dopiero przy komunikacji z APNs przez certyfikat TLS; potwierdzi pierwszy przebieg dowodowy `bez_wysylki` (błąd walidacji wskaże brakujące uprawnienie).
**Sprawdzenie:** zrzut ekranu App ID z włączonymi trzema możliwościami.

## A4. App ID celów: `.share`, `.widget`, `.watchkitapp`
**Po co:** każdy cel (rozszerzenie „Udostępnij”, widżet/Live Activity, aplikacja na zegarek) ma własny identyfikator pakietu (`targets/*/expo-target.config.js`: `bundleIdentifier` `.share`, `.widget`, `.watchkitapp` względem `com.apps4brew.knitting`). Eksport w `testflight.yml` podpisuje każdy cel profilem dystrybucyjnym.
**Kroki** (Apple, „Register an App ID”), po trzy razy: **Identifiers** → **+** → **App IDs** → **Continue** → typ **App** → **Continue** → Description (`Oczko share`, `Oczko widget`, `Oczko watch`) → **Explicit** → Bundle ID:
- `com.apps4brew.knitting.share` — dodatkowo zaznacz **App Groups** → Configure → `group.com.apps4brew.knitting` (to jedyny cel z grupą: `targets/share`);
- `com.apps4brew.knitting.widget` — bez dodatkowych możliwości (Live Activity nie jest możliwością App ID);
- `com.apps4brew.knitting.watchkitapp` — bez dodatkowych możliwości.
Potem **Continue** → **Register**.
**Źródło:** https://developer.apple.com/help/account/identifiers/register-an-app-id (odczyt 2026-11-01): „There are two types of App IDs: an explicit App ID, used for a single app, and a wildcard App ID… Beginning with Xcode 11.4, a single App ID can be used to build iOS, macOS, tvOS, and watchOS apps.”
**Otwarte [DO USTALENIA]:** czy to w ogóle trzeba robić ręcznie — podpis automatyczny Xcode (z kluczem API i `-allowProvisioningUpdates`) może te identyfikatory zarejestrować sam (Apple, „Automatic Signing Controls” zakłada, że Xcode rejestruje nowe App ID: https://developer.apple.com/help/account/access/automatic-signing-controls, odczyt 2026-11-01), ale nie ma dowodu, że robi to z kluczem API i z przypisaną grupą. Rejestracja ręczna jest tania i pewna; pierwszy przebieg dowodowy pokaże, czy była potrzebna.
**Sprawdzenie:** zrzut listy App IDs z czterema wpisami `com.apps4brew.knitting*`.

## A6. Schemat CloudKit: Development → Production — **po audycie (P-320); jeszcze nie rób**
**Dlaczego dopiero po audycie:** wdrożenie do Production jest **nieodwracalne** — Apple (https://developer.apple.com/documentation/cloudkit/deploying-an-icloud-container-s-schema, odczyt 2026-11-01): „To prevent conflicts, you can’t delete record types or fields that are already in production.”; archiwalny przewodnik CloudKit (https://developer.apple.com/library/archive/documentation/General/Conceptual/iCloudDesignGuide/DesigningforCloudKit/DesigningforCloudKit.html, odczyt 2026-11-01): „After you deploy the schema to the production environment, you can still modify the schema in the development environment but can’t delete record types and fields that were previously deployed.”; i o zmianach później: „After you deploy the schema to the production environment, you can add fields to a record, but you cannot delete a field or change its data type.” Audyt kandydata może zmienić schemat (`cloudkit/schemat.ckdb`, generowany z `docs/architektura/icloud-tabele.json`), a zbędnego typu albo pola po wdrożeniu nie usuniemy — dlatego wdrożenie dopiero po audycie, na schemacie z kandydata.
**Stan wiedzy (do późniejszej decyzji, nic z tego nie jest zadaniem teraz):** (1) Aplikacja z TestFlight i z App Store używa środowiska **Production** — archiwalny przewodnik: „When you are ready to upload your app to iTunes Connect to distribute your app using TestFlight or the store, Xcode automatically configures your app to use the production environment.”; „When you are ready to distribute your app for testing, you migrate the development schema to the production environment using CloudKit Dashboard.” (dokument archiwalny — szczebel 1, ale stary; potwierdzi pierwszy przebieg: `com.apple.developer.icloud-container-environment` w uprawnieniach `.ipa`). Bieżąca strona: „Apps in the App Store can access only the production environment. Before you publish your app, you must deploy the development schema to the production environment…” (2) Wdrożenie (krok właściciela, gdy przyjdzie czas): „Sign in to CloudKit Console at https://icloud.developer.apple.com/. Select the CloudKit Database app. In the top section, choose your container from the list. On the left, select Deploy Schema Changes. Review the pending deployment changes and click Deploy.” (3) Najpierw schemat trzeba zainstalować w Development: https://developer.apple.com/documentation/cloudkit/integrating-a-text-based-schema-into-your-workflow — „The CloudKit command line tools download, verify, and install a schema to your container’s sandbox environment, while the CloudKit dashboard promotes a schema to the production environment.” Składni `cktool` nie potwierdzono (ADR-0005, rejestr Apple 21b: `xcrun cktool --help` na runnerze macOS), a token zarządzania to nowy sekret.
**Decyzja D-A6 dla koordynatora (po audycie, P-087):** (a) instalacja schematu w Development przez workflow na `macos-26` z tokenem zarządzania (sekret w środowisku `release`), potem właściciel klika **Deploy Schema Changes** — zgodne z ADR-0005 · (b) właściciel instaluje schemat sam z Maca z Xcode — Maca nie potwierdzono (`docs/fakty-wlasciciela.md`) · (c) schemat powstaje „w locie” przy uruchomieniu zbudowanego w trybie deweloperskim — wymaga Maca. Rekomendacja: (a). **Skutek dla testów:** build TestFlight z iCloud ukrytym (`ICLOUD_W_1_0 = false`) nie potrzebuje schematu w Production; widoczny iCloud w buildzie TestFlight (P-290) już tak — kolejność: audyt kandydata → A6 → test iCloud (ZM-06).

## C1. Content Rights w App Information — po audycie (P-349 (1), P-320); jeszcze nie rób
**Po co:** App Store Connect nie pozwala dodać wersji do zgłoszenia („Add for Review”), dopóki pole Content Rights jest puste (Trening, lekcja L-028: zablokowało go 30.10.2026). Odpowiedź to Twoja deklaracja prawna na Twoim koncie; uzasadnienie dla Oczka i odrzucona opcja „No” są w `sklep.md` §3 krok 11.
**Gdzie:** https://appstoreconnect.apple.com/apps → Oczko → w pasku bocznym **General → App Information** → pole **Content Rights**.
**Kroki:**
1. W polu Content Rights wybierz odpowiedź, że aplikacja zawiera, pokazuje lub otwiera treści osób trzecich, i potwierdź, że masz do nich prawa (**Yes**, jak w Treningu). Etykiety przycisków mogą się różnić od mojego opisu — liczy się odpowiedź Yes.
2. Zapisz (**Save**).
**Czas:** 2 min [OCENA]. **Kategoria podatkowa:** nic nie zmieniasz — bez zmiany Apple przypisuje „App Store software” (`sklep.md` §3 krok 12); zmiana tylko, jeśli doradca podatkowy tak zaleci.

## C2. Age Rating: „Unrestricted Web Access” → 16+ (10-wydanie-003, P-393 / DEC-20 a)
**Po co:** import strony WWW (Projekt → „Add pattern…” → adres strony) jest w 1.0 i ładuje dowolny adres wskazany przez użytkownika. **Gdzie:** https://appstoreconnect.apple.com/apps → Oczko → pasek boczny **General → App Information** → sekcja **Age Ratings** → przycisk **Set Up Age Ratings** (przy zmianie istniejących odpowiedzi: **Edit** na górze strony App Information).
**Kroki:**
1. W oknie, które się otworzy, w liście **in-app controls and capabilities** zaznacz **Unrestricted Web Access** (nie zaznaczaj Parental Controls, Age Assurance, User-Generated Content, Social Media ani Messaging and Chat — aplikacja ich nie ma; wyjątek: jeśli kwestionariusz pokaże zdolność, która według Ciebie jednak występuje, wybierz ją i napisz mi o tym), kliknij **Next**.
2. 3. W **Age Categories and Override** wybierz **Not Applicable** (bez „Made for Kids”, bez „Override to Higher Age Rating”). Sprawdź w sekcji Additional Information, że wyliczona kategoria to **16+**.
